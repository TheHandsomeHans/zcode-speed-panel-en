# AGENTS.md

ZCode Speed Panel: Tauri 2 + Rust desktop tool (Windows / macOS dual-platform), measures ZCode CLI streaming output speed in real time and tallies today's token usage, with network speed monitoring (whole-machine measurement + session-traffic estimate split). Frontend is framework-free TypeScript + Canvas (Vite), backend Rust reads from `~/.zcode/cli/db/db.sqlite` (read-only), process IO counters, and network interface counters.

## Commands

```bash
npx tsc --noEmit                    # Frontend type check (must run after editing src/*.ts)
npm run build                       # tsc + vite build
cd src-tauri && cargo test          # Rust unit tests (48, incl. synthetic end-to-end, calibration estimator benchmark_*, update/net-monitor pure functions)
cd src-tauri && cargo check         # Backend compile check
npm run tauri dev                   # Dev run (user keeps one dev instance running; code changes hot-restart it)
npm run tauri build                 # Release build (Windows NSIS / macOS dmg, per host platform)
# Cross-build the Apple Silicon package on Intel Mac:
rustup target add aarch64-apple-darwin
MACOSX_DEPLOYMENT_TARGET=11.0 npm run tauri build -- --target aarch64-apple-darwin --bundles dmg
python scripts/live_vs_true.py      # Reconciliation: live reading vs persisted ground truth
python scripts/cal_bench.py         # Benchmark: calibration estimator replay of real samples (must run before/after changing the estimator, key-rules #5)
python scripts/estats_probe.py      # Re-verify per-connection TCP ESTATS byte availability (key-rules #14 evidence; concluded: not available with normal privileges)
```

## Release flow (v* tag → CI auto-creates Release)

1. **Bump version in three places in sync**: `src-tauri/tauri.conf.json` (runtime authority, the updater relies on it for comparison), `src-tauri/Cargo.toml`, `package.json`, then `cd src-tauri && cargo check` to refresh `Cargo.lock`;
2. Commit and push main (plain push does not trigger CI, saving runner time);
3. **Tag push**: `git tag vX.Y.Z && git push origin vX.Y.Z` — CI auto-builds and creates a GitHub Release (Windows setup/portable exe + macOS dual-arch dmg, Release name and placeholder body generated by build.yml template);
4. After build completes, polish the release note: `gh release edit vX.Y.Z --notes-file <changelog.md>` (describe user-visible changes; first release of a new architecture / renamed artifacts must also sync `updater::pick_asset`, see key-rules #12 and features.md "CI & Release").

Note: forgetting to bump `tauri.conf.json` makes the new Release's tag equal to the in-app version → updater silently judges "already latest" (key-rules #12).

## Architecture overview

```
src-tauri/src/metrics.rs   Data layer: usage library polling + daily aggregation (Engine/Aggregator, pure functions testable)
src-tauri/src/liveio.rs    Real-time speed: cross-platform (platform sub-module: Windows process-handle IO / macOS libproc+rusage) + platform-parameterized cleaning (CleanParams)/integration/ground-truth calibration (consistency calibration samples → cal_estimate recent-weighted median + AR1 shrinkage estimator; accuracy benchmark scripts/cal_bench.py + tests benchmark_*) + multi-task process-set aggregation (pick_pid_set/merge_streams, attribution hysteresis / cross-process sample guards) + round-average drift auto-recalibration (RoundDrift)
src-tauri/src/netio.rs     Network speed monitoring: whole-machine interface counters (win GetIfTable 32-bit per-interface modular diff / mac getifaddrs dedup) + session-traffic estimate split (token estimate ≈) + TCP connections grouped by process (win only) + daily cumulative persistence (the snapshot-artifact monitoring layer and snapshot guard card were removed along with ZCode discontinuing the snapshot feature, 2026-09-28)
src-tauri/src/updater.rs   In-app update: GitHub Releases check/download/install (pure functions parse_version/is_newer/pick_asset testable; artifact naming coupling see key-rules #12)
src-tauri/src/autostart.rs Autostart: settings dialog tri-state (off / boot autostart / follow ZCode); registry HKCU Run (winreg, win target only) / LaunchAgent plist (mac hand-written XML) is the single source of truth, no local config file; follow relies on `--zcode-follow` launch arg to wait silently + 2s polling `any_zcode_process` (liveio platform) to wake (mac branch not verified on real hardware)
src-tauri/src/main.rs      Application layer: polling thread, update-check thread, window mode/position persistence, tray (mac menu bar + dynamic Dock two-state: full panel Regular / floating window Accessory), DebugLog
src-tauri/examples/        dump/verify debug tools (#[path] include src; changing public API requires sync)
src-tauri/capabilities/    Tauri frontend permission whitelist (window API must be allowed here)
src/                       Frontend: main.ts assembly + module show/hide settings (top bar ⚙, localStorage modules.v1) + settings dialog "Autostart" section (autostart_get/autostart_set) + gauges.ts drawing / model_stats.ts curve card "Model Detail" view (toggle mutually exclusive with overall curve, legend chips multi-select) / pet.ts desktop pet / mock.ts preview
public/pets/               Pet pack resources; scripts/*.py debug log analysis; .github/workflows/ CI
```

Data flow: poller thread ticks every ~700ms → `Engine.poll` (SQLite incremental ingestion) → `Engine.snapshot` (daily aggregation + 90-bucket curve) → `LiveIo.measure` (process-set cleaning/gating/consistency calibration → overwrites live values; aggregates total throughput + per-task breakdown when multi-task concurrent) → `NetIo.tick` (whole-machine interface diff + connection attribution → network card fields and session-traffic estimate) → tray status item update → DebugLog (JSONL) → `emit("metrics")` → frontend render.

Startup path (parallel to the polling chain above): when `--zcode-follow` (autostart.rs follow mode), setup skips `window.show()` and waits silently (tray only), detection thread polls `any_zcode_process()` every 2s, on hit calls `show_main` to reveal the panel; with no arg, `window.show()` runs as usual.

## Conventions

- Commit messages in English, first line summarizes root cause/behavior.
- mac uses native Overlay title bar (real system traffic lights, green dot = native fullscreen — only Regular app identity grants fullscreen, Accessory is always auxiliary fullscreen); Dock two-state: full panel shows icon (Regular), collapsing floating window auto-hides (Accessory, app does not quit). Windows has no system title bar: top bar is custom-drawn (`#app-header` + `data-tauri-drag-region`, left side is `app-icon.png` app icon); clicking ✕ = collapse to floating window, exit goes through tray / right-click menu. mac Cmd+Q also collapses to floating window — true exit is only via tray "Quit" and floating window right-click "Exit app" (three lines of defense: custom menu has no quit item, ExitRequested fallback, prevent_exit).
- Platform differences are concentrated in `liveio.rs`'s `platform` sub-module and `CleanParams` (Windows/mac parameter tables see `docs/features.md`); changing cleaning logic must verify both platforms' bases; FFI struct mirrors must carry `offset_of!` compile-time assertions (see key-rules #10).
- All UI dropdowns are custom-drawn (`.dropdown`), native `<select>` is disabled — WebView2 dropdown follows system light theme, text is invisible in dark UI (key-rules #8); new interactive components in the top bar must be added to the drag/double-click exclusion selectors.
- Gauge colors: speed gauge tier colors defined at top of `src/gauges.ts` in `SPEED_TIERS` (six tiers: 0–40 green / 40–80 yellow-green / 80–160 yellow / 160–240 orange / 240–320 red / 320+ magenta, whole-arc color change not segmented, background track always gray), main gauge, mini gauge, "last round" corner-badge small gauge (`BadgeGauge`), and capsule/pet last-round reading share it (`speedColor()` unified color lookup); floating window size changes must sync `main.rs`'s `FLOAT_*_SIZE`, `docs/features.md`, and README. Pet window is "square sprite area + top `PET_BUBBLE_RESERVE` bubble reserve band", during multi-task (≥2 processes, 3-tick debounce) it additionally grows upward by `PET_TASK_EXTRA` — size basis is distributed across `apply_mode`/`set_float_size`/`apply_pet_size` three locations (`pet.ts` positions sprite area by canvas short edge), changing one requires syncing the others; bubbles grow upward, sprite does not shrink.
- CI does not auto-trigger on push (saving runner time): builds go through `v*-en` tags (auto Release: Windows exe + macOS dual-arch dmg) or Actions page manual Run workflow (Artifacts: windows / macos-x86_64-apple-darwin / macos-aarch64-apple-darwin); changing workflow trigger logic must sync README and `docs/features.md`. **Release = three-place version sync bump (`tauri.conf.json` authoritative / `Cargo.toml` / `package.json`) + `v*-en` tag** — in-app update matches installer by Release asset name suffix, build.yml artifact naming and `updater::pick_asset` are the same protocol, changing one requires syncing the other (key-rules #12).
- Full panel and floating window positions are independently remembered (`~/.zcode/speed-panel-mode.txt`); floating window size uses logical pixels, physical conversion goes through `scale_factor()`, multi-screen positioning must use `clamp_to_screen`.
- Full panel module show/hide and ordering is in the top bar ⚙ settings (localStorage `modules.v1`; default shows Dashboard / Network Speed / Curve, all visible). Each module is wrapped in a `.module-wrap[data-module]` (`display:contents`, the card remains a main flex item) — **new panel module must sync**: index.html add wrapper layer + main.ts's `MODULE_DEFS`/`MODULES_DEFAULT_ORDER`/`MODULES_DEFAULT_HIDDEN`, see features.md "Module Show/Hide & Ordering" for details.
- Autostart state **is not stored in a local config file**: Windows registry `HKCU\…\Run` / macOS LaunchAgent plist is the single source of truth, the settings UI reads back the real state (manually editing the registry or deleting the plist is faithfully reflected), not stored separately in `speed-panel-*.txt` — avoids state drift between two locations. Platform differences are concentrated in `autostart.rs`'s `#[cfg]` branches, mac branch not verified on real hardware (see features.md "Autostart").

## Documentation maintenance (required on every code change)

**Any program modification (behavior, feature, UI, semantics, parameter, file format) must update documentation in the same commit**:

- Change feature behavior/parameter/interaction → update `docs/features.md`; change architecture/rules/pitfall → update this file and `docs/key-rules.md`;
- User-visible change → update `README.md`;
- New debug/analysis script → register in this file's commands section and `docs/features.md`.

Documentation out of sync with code is considered an incomplete change. Pre-commit self-check: for every behavior change in `git diff`, is there a corresponding documentation change.
